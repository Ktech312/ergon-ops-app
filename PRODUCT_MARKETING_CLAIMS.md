# Marketing Claim Matrix

Internal reference only — not marketing copy, not for publication. Purpose: separate what can be
truthfully claimed about Ergon today from what's in development or roadmap-only, so no future
marketing material states a capability as shipped when it isn't. Every "Verified today" row is
grounded in the evidence already gathered across `PRODUCT_TENANCY_AUDIT.md`, `PRODUCT_PHASE1_PLAN.md`/
`PRODUCT_PHASE2_PLAN.md`, and `PRODUCT_GLOSSARY.md` — not asserted fresh here.

| Capability | Status | Evidence / what's actually true | What's needed before a public claim |
|---|---|---|---|
| "Real-time inventory tracking across purchasing, warehouse, and projects" | **Verified today** | `inventory_items`/`inventory_balances`/`inventory_movements` are real, live tables with a working receive/allocate/transfer/build flow, confirmed throughout this session's evidence and the existing HANDOFF history | None — this is real and can be claimed as-is |
| "Sales quotes with a customer-facing, no-login proposal experience" | **Verified today, narrower than it sounds** | `sales_quotes`/`sales_quote_proposals` are real; a public, token-based proposal page exists (`ProposalPublicPage`) where a customer can approve/reject/request revision with no login | Claim the mechanism, not a full "CRM" — see the Opportunity/Contact gaps below before implying a complete sales pipeline |
| "Multi-tenant / supports multiple companies" | **NOT true — do not claim** | Exactly one workspace exists in production; RLS does not restrict any table in the Clients/Sales Quote cluster by workspace yet; most of the other 80+ tables in the schema have no workspace concept at all (`PRODUCT_TENANCY_AUDIT.md` §2/§9) | Full Phase 3 (RLS on the Clients/Sales Quote cluster, `PRODUCT_PHASE3_PLAN.md`) plus every later phase in `PRODUCT_TENANCY_AUDIT.md` §9 (Storage, singleton tables, server-route audit) — this is a multi-phase program, not a near-term claim |
| "Tenant-isolated / your data is never mixed with another company's" | **NOT true — do not claim** | Same as above; today there IS only one company's data in production, so nothing is *currently* mixed, but the *architecture* does not yet enforce isolation if a second workspace existed | Same as above — this claim requires Phase 3's denial tests (`PRODUCT_PHASE3_PLAN.md` §3) to actually pass, not just the schema work to exist |
| "Full CRM — leads, opportunities, contacts, deal pipeline" | **NOT true — do not claim** | No `Opportunity`, `Contact`, or pipeline-stage table exists anywhere in the schema (`PRODUCT_GLOSSARY.md`) | Requires the CRM capabilities identified as "essential first-release" in the Sales product-discovery work (Priority 6 of this session's queue — see that report once finalized) |
| "Automatic quote-to-project handoff" | **Verified today, with one caveat** | `createProjectFromClosedWonQuote()` really does copy locations/BOM/items/images and links back via `source_sales_quote_id` when a quote is marked Closed-Won | A second, older, unlinked "Pull BOM from Closed Sales" path still exists in parallel (`PRODUCT_PHASE2_PLAN.md` §3.4) — don't claim this is the *only* path until it's retired or fully superseded |
| "Role-based permissions" | **Verified today** | `app_user_roles`/`workspace_member_roles` (10 role keys), `requireRole` middleware on API routes, role-gated Admin panels — all real and confirmed throughout this session | None — real, can be claimed |
| "Configurable without code — branding, templates, forms, roles, notifications" | **Partially true — claim narrowly** | Company name/logo, Notification Rules, Form Builder, Schedule Templates, and Proposal Template Sections ARE genuinely admin-configurable no-code today (`PRODUCT_TENANCY_AUDIT.md` §5) | Don't imply *full* no-code company setup — vertical-specific terminology, the role vocabulary itself, and module/nav enablement are still code-level today (see the onboarding/configuration design work, Priority 7 of this session's queue) |
| "SaaS subscription management for your own service contracts" | **NOT true — do not claim** | `projects.saas_*` columns are placeholder-only, explicitly documented as such in `HANDOFF.md` | Requires real product design and population, not just schema columns |
| "Client Ledger / installed-asset lifecycle tracking" | **Verified today** | `installed_assets` (migration 089) is real, with expected-lifespan/kickoff/warranty date tracking | None — real, can be claimed, though "Client Ledger" itself is a UI view, not its own table (fine to call it a feature; don't imply a separate ledger database) |
| "Mobile-ready" | **Mostly true, verify before claiming "fully"** | Extensive, deliberate mobile-table-to-card-list rollout with an established, applied convention (`HANDOFF.md` standing rules) — but the read-only mobile-workflow audit from this session's queue (Priority 8) should confirm there are no remaining gaps before an unqualified "fully mobile" claim |
| "Offline-capable photo uploads" | **Verified today, scope it precisely** | An offline upload queue exists and has been deliberately extended to cover Shipping's packing photos matching Site Builder/Locations photos (`HANDOFF.md`) | Confirm via the mobile-workflow audit (Priority 8) that this queue is actually used everywhere photos are captured, not just the flows explicitly mentioned in HANDOFF's history, before claiming blanket "offline support" |
| "Accessible / WCAG-compliant" | **Unverified — do not claim yet** | No accessibility audit had been performed before this session's queue; Priority 8's accessibility audit (in progress as of this writing) is the first real evidence gathering on this | Do not make any accessibility claim until that audit's findings are addressed, not just gathered |
| "Enterprise-grade security" | **Do not use this phrase at all** | Vague, unverifiable marketing language this matrix exists specifically to avoid. Concrete, evidence-backed sub-claims (role-based access, audited security-definer functions with minimized grants, soft-delete audit trails) can be made individually with their own evidence, but never bundled into an unfalsifiable phrase like this | Replace with specific, true statements only |

---

**Standing rule for using this matrix**: a "Verified today" row can be used in a public claim as
written. A "Partially true" row must be scoped exactly as narrowly as its evidence column states —
do not round up. A "NOT true — do not claim" row must never appear in public-facing material,
including implicitly (e.g., a screenshot that visually suggests multi-company support). When a
capability moves from one status to another, update this file in the same pass, the same way
`PRODUCT_TENANCY_AUDIT.md`/`PRODUCT_START_PLAN.md` were reconciled tonight rather than left stale.
